# كتابي أنا

تطبيق ويب عربي من اليمين إلى اليسار، يصنع للطفل كتاباً مصوّراً قصيراً يحمل اسمه، عن أذكار المواقف اليومية. بلا حسابات، وبلا حفظ لاسم الطفل أو سجلّه.

**الحالة: نسخة هندسية تجريبية، والمراجعة الشرعية لم تتم بعد.** كل المحتوى بحالة `pending`، واستدعاءات الذكاء الاصطناعي معطّلة افتراضياً (`AI_ENABLED=false` و`AI_IMAGES_ENABLED=false`). لا شيء هنا اعتماد شرعي ولا دليل على أثر تعليمي. النصوص منقولة من منتج «حصن الطفل». أصل الكود المشترك موثّق في [NOTICE](NOTICE) و[docs/ORIGIN.md](docs/ORIGIN.md).

**توثيق المحتوى ومصادره الشرعية وطريقة التحقق منها:** [docs/SOURCES.md](docs/SOURCES.md).

## نطاق النسخة التجريبية

ملف الفكرة المسلَّم وعد بـ12 نصاً في 6 مواقف، و3 مناسك. هذه النسخة تعرض 4 نصوص أذكار في 3 مواقف (الاستيقاظ، لبس ثوب جديد، الطعام). والمنسك الواحد (التلبية) لم يصل نصه بعد، فحزمة المناسك فارغة حالياً.

السبب أن الوقت المتاح يومان، والهدف تجربة كاملة لا محتوى كاملاً. والبنية لا تتغير بإضافة المحتوى: حزمتان بالصيغة نفسها في `packages/core/data/packs/`، فإضافة نص عمل محتوى لا عمل برمجي. ويُبلغ `npm run verify:content` عن أي فرق بين العدد الفعلي والمعلَن، دون أن يُفشل البناء.

**حدّ الطلبات في هذه النسخة:** إن لم يُضبط `SUPABASE_URL` يعمل الحد في ذاكرة الخادم: 30 طلباً في الدقيقة لكل زائر، لكل نسخة خادم على حدة، وليس مشتركاً بينها ولا يومياً. يكفي هذا والتوليد معطّل لأن الطلب لا يكلّف شيئاً. وقبل تشغيل `AI_ENABLED=true` ضعوا سقفاً للإنفاق في لوحتي Gateway وfal، أو اضبطوا Supabase ليصير الحد مشتركاً.

## حدود المنتج

- لا يفتي، ولا يفسّر، ولا يعلّم أحكاماً. يعرض النص كما ورد، ومعناه كما كتبه فريق المشروع، ويرفض ما سوى ذلك ويحيل إلى الوالدين أو أهل العلم.
- **الشرح المعروض** يُصاغ آلياً من المعنى المكتوب ليناسب عمر الطفل وجنسه. النموذج لا يستلم نص الذكر ولا اسم الطفل، ويُفحص ناتجه قبل العرض:
  - **الفحص النصي في الخادم:** يرفض أي تطابق مع نص الذكر، وأي حكم فقهي، وأي اقتباس، وأي وعد أو ترهيب غير موجود في المعنى.
  - **فحص الزيادة والحذف:** يعتمد نموذج تحكيم ثانياً، وليس قاعدة ثابتة.
  - الراسب يُعاد مرة واحدة، ثم يُعرض المعنى كما كُتب.
- **عند تعطّل المزوّد أو تجاوز المهلة أو `AI_ENABLED=false`:** يُعرض المعنى كما هو، وتحته سطر «المعنى كما كُتب في المصدر». والمعنى مكتوب بصيغة المذكر، فيبقى بالمذكر حتى للبنت في هذه الحالة.
- **مقارنة «الطفل نفسه» بين الصور** تُسجَّل للمراجعة ولا تُسقط صورة ولا تطلب إعادتها، لأن حكمها تقديري وغير مستقر مع نموذج الرسم. والفحص بأسئلة نعم/لا (الأصابع، واللباس، والكتابة، والوجه، والشعر، وشخص آخر) يُسقط ويُعيد كما هو.
- **الشروح الستة عشر** (4 أذكار × فئتين × جنسين) تُولَّد مرة بالأمر `npm run warm:explanations` وتُحفظ في المستودع، وتُقرأ في `docs/EXPLANATIONS.md`.

## دور الذكاء الاصطناعي

**يُستعمل في:**

- **الصورة:**
  - تُولَّد لقطة مرجعية واحدة للطفل، ومنها صورة الغلاف ومشاهد الكتاب، بلباس واحد ثابت. والمرجع يُرسل إلى نموذج الرسم كما خرج، ولا تُستعمل صورة الغلاف المقطوعة الخلفية مرجعاً أبداً.
  - تمرّ كل صورة بفحص نعم/لا، وعند الفشل يُستعمل رسم احتياطي. وفحص ثبات الشخصية عبر الصفحات يُسجَّل فقط.
- **فهم إجابة الطفل وبناء الشرح عليها:**
  - قبل الكتاب، وخارجه، سؤال قصير لكل موقف. يجيب الطفل برقاقة أو بكلماته (للفئة 9–12 فقط)، أو بـ«ما أعرف» أو «تخطّي».
  - يبني النموذج الشرح على إجابته:
    - يصدّق القريب منها ويكمل ما نقص؛
    - ويعالج البعيد بلا تخطئة.
  - ويمرّ الشرح بالفحوص نفسها.
- **التكيّف بالعمر والجنس:** صياغة الشرح لفئة 5–8 أو 9–12، بخطاب الولد أو البنت.

**ولا يُستعمل في:**

- **النص الشرعي:** يُعرض كما ورد، ولا يُرسل إلى أي نموذج.
- **المعنى:** يكتبه فريق المشروع، والشرح لا يزيد عليه.
- **الأماكن المقدسة:** لا تُولَّد صورها، ولا تُمرَّر صورها إلى أي نموذج. ما فيه مكان مقدس يُركَّب على خلفية معتمدة جاهزة.

## الخصوصية

- لا حسابات. واسم الطفل لا يغادر المتصفح، ويُستبدل برمز إن كتبه الطفل داخل إجابته.
- اسم الطفل يظهر في الغلاف وفي صفحة الشرح التي تخاطبه به، ولا يظهر في صفحة النص ولا في الطبقات المرسومة.
- **رفع صورة الطفل** معطّل افتراضياً (`ALLOW_UPLOAD=false`). حين يُفعَّل:
  - يقبل صورة واحدة بصيغة JPG أو PNG، حتى 2 ميجا، ويُفحص نوعها الحقيقي في المتصفح وفي الخادم.
  - تُرسل إلى خدمة الرسم fal مرجعاً لرسم الشخصية فقط، ثم تُنسى: لا تُحفظ، ولا تُسجَّل، ولا تُرسل في أي طلب آخر. وبقية الصور تُرسم من الشخصية المرسومة لا من الصورة.
  - راجعوا سياسة الاحتفاظ لدى fal قبل التفعيل، فالصورة تصل إليها.
- ما يكتبه الطفل في خطوة السؤال:
  - يُستعمل في طلب الشرح ويُنسى: لا يُحفظ ولا يُطبع ولا يظهر في الكتاب ولا في صفحة الختام.
  - يمرّ قبل إرساله بفحص الأزمة وفحص المحتوى المقيَّد.
  - ما سقط في فحص الأزمة لا يغادر الخادم.

## أوامر المحتوى

- `npm run review:content`: يولّد `docs/CONTENT.md` لمراجعة كل عنصر، مع قائمة ما يحتاج مراجعة، ولا يعدّل أي حقل.
- `npm run verify:content`: يتحقق من مطابقة النصوص لبصماتها، وغياب المفاتيح، وعدم حفظ اسم الطفل أو تسجيله، ونجاح الاختبارات.
- `npm run warm:explanations`: يولّد الشروح الستة عشر مرة واحدة بمفتاح Gateway، ويحفظ ما اجتاز الفحص فقط.
- `npm run review:explanations`: يولّد `docs/EXPLANATIONS.md`، وفيه المعنى بجانب كل شرح.
- `npm run content:hashes`: يسجّل بصمات جديدة بعد تغيير مقصود في نص وصل من المالك فقط.

## التشغيل

```sh
npm ci
cp apps/qindeel/.env.example apps/qindeel/.env.local
npm run dev:qindeel      # http://localhost:3001
```

على Windows استعمل `Copy-Item` بدل `cp`، أو `scripts/start-local.ps1`. ملف `.env.local` مستبعد من Git؛ لا تضع فيه قيماً حقيقية في أي ملف متتبَّع.

```sh
npm run typecheck
npm test
npm run build
npx playwright install chromium && npm run test:e2e
```

### متغيرات البيئة (الأسماء فقط؛ انظر `apps/qindeel/.env.example`)

`CONTENT_MODE` (`preview` أو `reviewed`)، `AI_ENABLED`، `AI_IMAGES_ENABLED`، `ALLOW_UPLOAD`، `AI_TEXT_MODEL`، `AI_VISION_MODEL`، `FAL_KEY`، `FAL_REFERENCE_MODEL`، `FAL_EDIT_MODEL`، `FAL_BACKGROUND_MODEL`، `AI_GATEWAY_API_KEY`، `SUPABASE_URL`، `SUPABASE_PUBLISHABLE_KEY`، `INTERNAL_API_TOKEN`.

بلا `SUPABASE_URL` يعمل حدّ الطلبات في الذاكرة، في التطوير والإنتاج. ومع `SUPABASE_URL` يلزم `INTERNAL_API_TOKEN` أيضاً، وإلا تُرجع نقاط الـAPI الرمز 503.

## النشر على Vercel

من لوحة Vercel، بلا أداة سطر الأوامر:

1. **Add New → Project**، ثم استورد هذا المستودع من GitHub.
2. **Root Directory:** `apps/qindeel`، مع إبقاء خيار تضمين الملفات خارج الجذر مفعّلاً، لأن التطبيق يقرأ من `packages/core`. والإطار Next.js يُكتشف وحده، وأوامر التثبيت والبناء تبقى على الافتراضي.
3. **Environment Variables:**
   - `CONTENT_MODE=preview` **إلزامي**. بدونه يعمل الإنتاج بوضع المحتوى المعتمد، ولا محتوى معتمد بعد، فتظهر المكتبة فارغة.
   - `AI_ENABLED=false` و`AI_IMAGES_ENABLED=false`.
   - لا يلزم غيرها في هذه النسخة. ولا يلزم `INTERNAL_API_TOKEN` ولا متغيرات Supabase.
4. **Deploy.** ثم افتح `/api/health` للتأكد.

توليد الصور معطّل في النسخة المنشورة لضبط التكلفة، ويعمل محلياً.

وعند تشغيل الشروح الحية: ضعوا سقف إنفاق في لوحة Gateway أولاً، ثم أضيفوا `AI_GATEWAY_API_KEY` واجعلوا `AI_ENABLED=true`، مع إبقاء `AI_IMAGES_ENABLED=false`، ثم أعيدوا النشر.

## البنية

- `apps/qindeel`: تطبيق Next.js ونقاط الـAPI. وكل نص يراه المستخدم خارج حزمة المحتوى في `apps/qindeel/lib/copy.ts`.
- `packages/core`: المحتوى، والتطبيع العربي، وبوابات السلامة والرفض، وتجميع الكتاب، والتوليد المقيَّد، والتحقق من الطلبات.
- `supabase`: جدول المحتوى المعتمد، وحصص الطلبات، ودالة `platform-quota`.
- `scripts` · `tests` · `docs`.

(أسماء المجلدات الداخلية مثل `apps/qindeel` و`@platform/core` باقية كما هي لأسباب تقنية، ولا تظهر للمستخدم.)
